# Dentiva Pro — Build, installer & release process (Phase 1)

## 1. Versioning
- Single source of truth: `dentiva/__init__.py :: __version__ = "1.0.0"`.
- Semantic versioning; the release artifact is tagged `v1.0.0`.
- Build metadata injected at build time into `dentiva/_buildinfo.py`
  (git commit, build date, Python version, Qt version) and shown in About →
  System details. The file is generated by the build step, never hand-edited.

## 2. Build pipeline (reproducible)

```
GitHub Actions (windows-latest)
  1. setup-python 3.11 (pinned) → python -m pip install -r requirements-build.txt
  2. tools/build/make_version.py        → dentiva/_buildinfo.py, version info resource
  3. tools/build/make_ico.py            → assets/icons/dentiva.ico (multi-resolution)
  4. tools/build/make_fonts.py          → static Noto instances + OFL notices
  5. ruff check/format --check ; mypy ; pytest (unit+integration+security)
  6. PyInstaller packaging/dentiva.spec (onedir)  → dist/DentivaPro/
  7. Inno Setup packaging/dentiva.iss    → dist/DentivaProSetup-1.0.0.exe
  8. checksums (SHA-256) + artifact upload
  9. clean-runner validation: silent install → --selftest → uninstall → reinstall
 10. on tag/manual dispatch: create GitHub Release, attach installer + checksums
     (fallback: commit the verified .exe into repository `dist/`)
```

Reproducibility measures: pinned dependency versions with hashes
(`requirements-build.txt`), a fixed runner image, no network access at build time
other than package installation, deterministic PyInstaller options
(`--noconfirm`, sorted inputs, `PYTHONDONTWRITEBYTECODE=1`), and the build info
file recording the exact inputs.

## 3. PyInstaller configuration
- Mode: **onedir** (faster startup, reliable Qt plugin discovery, easier support
  diagnostics) shipped inside the installer; `--windowed` (no console).
- Explicit `hiddenimports` for SQLAlchemy dialects, Alembic migration scripts
  (collected as data), `argon2`, `openpyxl`, `PIL` plugins.
- Bundled data: `assets/` (icon, fonts, OFL notices), `dentiva/data/migrations/`,
  `THIRD_PARTY_NOTICES.md`, `LICENSE`.
- Qt plugin selection: only `platforms`, `imageformats` (png/jpeg/svg), `styles`,
  `printsupport`, `iconengines`; QtWebEngine/QtMultimedia/Qt3D excluded.
- Post-build verification: the frozen app is launched with `--version` and
  `--selftest` on the runner.

## 4. Installer (Inno Setup 6)
- Product name **Dentiva Pro**, publisher **Shohan Khan**, version from
  `dentiva/__init__.py`.
- Default per-machine install to `{autopf}\Dentiva Pro`; per-user fallback
  (`{localappdata}\Programs\Dentiva Pro`) when the user lacks admin rights.
- Files: the whole PyInstaller `dist/DentivaPro` tree (no external runtime
  dependency; the Visual C++ runtime is bundled/checked).
- Shortcuts: Start Menu folder `Dentiva Pro` (app + uninstall), optional desktop
  shortcut (checkbox, default on), both using `dentiva.ico`; `AppUserModelID`
  set so the taskbar icon and pinned shortcuts use the correct icon.
- Uninstall entries with `UninstallDisplayName`, publisher, version, icon,
  `UninstallFilesDir`; registry cleanup on uninstall; **data is never deleted unless
  `/REMOVEDATA=1` is passed**, which shows an extra typed warning page.
- Reinstall/upgrade: files are overwritten in place; the app detects a newer
  schema on first launch and migrates after taking an automatic pre-upgrade backup.
- Silent switches supported for CI: `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART
  /LOG=install.log [/REMOVEDATA=1] [/DESKTOPSHORTCUT=0]`.
- Post-install page offering "Launch Dentiva Pro" (default checked).

## 5. Activation in the delivery flow
The installer does not ask for the activation code; the **application** does, on
first launch (offline). This keeps the installer simple and lets the clinic
activate after copying a verified installation. The code is entered once, verified
entirely locally (ADR-0006), and the activation record is written to the user's
data directory.

## 6. Release gates (REQ-REL-002)
Before the final `.exe` is built, all of the following must be evidenced in the
release report: requirements audit, architecture audit, database & relationship
audit, RBAC audit, security audit, UI audit, UX audit, accessibility/usability
audit, print audit, PDF audit, backup/restore audit, performance audit, stress
test, dependency/licence audit, code-quality audit, dead-code review, TODO review,
error-state review, installer review, uninstaller review, clean-machine install
test, end-to-end workflow test, regression test, GitHub Actions validation and
final verification. Each gate has a named artifact (test job name, report file or
screenshot bundle).

## 7. Release artifacts
- `DentivaProSetup-1.0.0.exe` (installer; primary deliverable)
- `SHA256SUMS.txt`
- `dist/` fallback copy of the verified `.exe` if a GitHub Release cannot be
  published (REQ-GIT-005)
- Release notes (features, system requirements, install/activation steps, known
  limitations stated honestly)
- Optional: `DentivaPro-1.0.0-portable.zip` (onedir archive) as a convenience for
  support scenarios — clearly marked as unsupported for regulated data.

## 8. Post-release
- `main` is tagged; the release branch stays for hotfixes (`1.0.x`).
- Support diagnostics: the user runs Help → System Health → "Export diagnostics"
  (logs, integrity report, config summary with secrets redacted) and attaches it.
